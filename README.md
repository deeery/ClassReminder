# StuMate — Android 课表与提醒 App

> 项目名：`StuMate-Android-Preview` · 手机上显示为 **StuMate**

一个 Android 课表 / 便签 / 上课提醒应用，使用 **Kotlin + Jetpack Compose + Room + Foreground Service** 构建。

## 功能

- **「今天」首屏** — 打开即知「现在该干什么」：正在上课时用**实心主色卡 + 倒计时**（「还剩 27 分钟」），没课则显示下一节；进入预警窗之前显示「**当前空闲**」与「距离下一件事 N 小时后」；下方是今天剩余时间轴（46dp 左对齐）与便签摘要（最多 5 条、Deadline 类优先、超量时末位换成灰色「…」省略栏）。时间每 30 秒自刷新
- **快速便签** — 随手记的便签列表：点「+」新增（默认置顶；若已高亮选中某条则插到它上方），单击选中高亮、双击直接进编辑，左下角浮出编辑 / 删除，点空白处取消选中；编辑对话框里带 **8 色调色盘**（选色后便签左端竖线、描边、光晕即时跟随，颜色以索引存库、深浅主题各取合适色值）与**分类选择**；长按整栏上下拖动排序（拖动时略微放大并抬起阴影）；左滑露出编辑按钮、大幅左滑直接滑出删除；「回撤」按钮（纯图标，与加号按钮同尺寸对齐）可撤销上一次操作
- **便签分类与 Deadline** — 分类共 7 项：空（默认）/ 工作 / 生活 / 学习 / Deadline / 自定义 / Deadline 自定义；后两类可改名，带 Deadline 的分类会显示**截止时刻 + 倒计时**徽章（过期用错误红），今天页的摘要里 Deadline 类自动上浮
- **顶栏问候语** — 按当前小时显示 `早上好。` / `午安。` / `下午好。` / `晚上好。` / `夜深了。`，下方接日期与周次
- **课程管理** — 添加 / 编辑 / 删除每周课程，数据持久化到 Room 数据库
- **PDF 课表导入** — 设置页可导入教务系统导出的课表 PDF（iText / Rotate 90 / UniGB-UCS2-H 编码），同一门课重复导入会覆盖而非重复添加；PDF 里没有具体时刻，导入后按默认作息推算，可逐条修改
- **周次过滤** — 支持 `1-16周` / `第6周` / `1-8周,10-12周` / `1,3,5周` / 单双周 `1-16周(单)` 等写法，按当前周决定显示与提醒；解析不出周次时视为「不确定」，不限制显示
- **智能提醒** — 前台 Service 每 30 秒轮询，课程即将开始或正在上课时发送高优先级通知
- **锁屏弹窗** — 可选全屏锁屏弹窗（LockOverlayActivity），不错过每一节课
- **周课表** — 底部栏切换「今天 / 课表 / 便签 / 设置」四个视图，课表支持表格 / 列表两种模式；右下角加号上方有**查看 / 编辑模式切换**（默认查看：眼睛图标，点课程只高亮选中并展开详情、不弹编辑框；点一下切编辑：铅笔图标，点课程直接进编辑对话框）；表格纵轴按**真实时间比例**（从本周最早一节课开始、随屏幕高度自适应），**点列头可高亮任意一天**——高亮列会加宽、左侧刻度换成那一天各事项的起止时刻；再点一次列头取消全部高亮，左侧退回等距的固定间隔；今天那一列的表头带「今日」角标（与手动高亮无关）。列表模式下高亮分**四级强度**（今天 / 悬停 / 按住 / 选中），正在上课的那一节额外挂一颗小圆点和柔光晕
- **动态前台通知** — 前台通知实时显示检测状态：正在上课/即将上课/今日课程概况
- **浅色/深色主题** — 三种模式：跟随系统、浅色、深色，设置页一键切换
- **国产 ROM 保活引导** — OPPO / 一加 / realme 机型在设置页显示「特殊权限」与「应用详情」两个入口（这类权限没有标准 API，只能引导用户手动开启；组件名失效时兜底到应用详情页，不会点了没反应）
- **开机自启** — 可开启开机自动启动提醒服务
- **模块化备份** — 设置页可把数据导出成一个 JSON 文件、也能从文件恢复；**课程表 / 便签 / 设置**三个模块各自独立，能单独导出 / 导入，也能一次整体带走（两种文件格式完全一样）；导入时逐模块勾选，并且**每个模块都要单独确认一次覆盖**（课表一次、便签一次）
- **自定义图标** — 支持启动器图标和通知栏图标

## 架构

```
MainActivity (单 Activity)
  └─ ClassReminderTheme (浅色/深色支持)
       └─ Surface + Scaffold
            ├─ TopAppBar × 底部导航栏（今天 / 课表 / 便签 / 设置）
            ├─ TodayScreen (今天：主卡 / 空闲态 / 剩余时间轴 / 便签摘要)
            ├─ WeekView (表格 / 列表两种模式，按周分组)
            ├─ NoteListView (快速便签：选中高亮 / 拖动排序 / 左滑 / 回撤)
            └─ SettingsPage (主题、权限、提醒设置、导入课表、ROM 引导)
  └─ MainViewModel ──→ Room Database
  └─ ClassReminderService (Foreground Service，每 30 秒轮询)
       └─ LockOverlayActivity (锁屏弹窗)
  └─ BootReceiver (开机自启)
```

## 更新日志

### v4.3 — 深色主色统一 Google Blue 600 · 课表高亮调淡 · 模块化备份 · 改名 StuMate

**1. 项目改名 `StuMate-Android-Preview`**

- Gradle `rootProject.name`：`ClassReminder` → `StuMate-Android-Preview`
- 启动器显示名：`ClassReminder` → **StuMate**（debug 变体 `StuMate-test`）
- 通知渠道名 `ClassReminder Service` → `StuMate 服务`
- **包名 `com.example.classreminder` 与类名不动** —— 应用名和包名是两回事，改包名要动全部 import、`namespace`、`applicationId`，收益只是「看起来更统一」，风险却是实打实的

**2. 深色主题的主色改用深色 Google Blue**

`DarkColors.primary`：`#8AB4F8`（Google Blue 200，官方深色那套提亮版）→ **`#1A73E8`**（Google Blue 600，与浅色同一个品牌蓝），`onPrimary` 随之从深蓝 `#0D2D62` 换成白色。

理由：深浅两套用同一个品牌蓝，高亮色才不会「一进深色就换了支蓝」。**代价要清楚**：`#1A73E8` 对 `#121212` 是 4.2:1、对卡片 `#1E1E1E` 是 3.8:1，**小字号正文达不到 AA 的 4.5:1**（大标题 / 图标 / 色块仍达标），所以主色只承担「高亮块、图标、按钮底、色条」这类角色，不写正文。

便签调色盘第 0 格仍是 `#8AB4F8` —— 它是便签竖线的**内容色**，要贴在深色卡片上看得清，且调色盘整体统一走 200 档。

**3. 深色课表-表格的高亮调淡**

深色下「非今日」列原来用 `surfaceVariant` α**0.85**，几乎铺成一块实心色，把课程块压了下去。这一版把整套强度收成一组**表头与列身共用**的常量（原来两边各自硬编码同一组数字，改一处漏一处就会「表头和列身深浅对不上、整列头重脚轻」），并整体调淡：

| 位置 | 浅色 | 深色 旧 → 新 |
|---|---|---|
| 今日列选中底 | 0.14 | 0.34 → **0.22** |
| 非今日列选中底 | 0.75 | 0.85 → **0.52** |
| 今日列常态弱底 | 0.035 | 0.07 → **0.05** |
| 悬停整列 | 0.022 | 0.05 → **0.04** |
| 列左右描边（今日 / 非今日） | 0.30 / 0.55 | → **0.26 / 0.42** |
| 课程块选中底 | 0.12 | 0.22 → **0.15** |
| 课程块选中光晕 | 0.17 | 0.30 → **0.24** |

**4. 模块化导入 / 导出**

设置页新增「数据备份」区块。三个模块 **课程表 / 便签 / 设置** 各自独立：

- **单独导出**：每个模块一行「导出」按钮
- **整体导出**：「导出全部」一次带走
- **导入**：选文件 → 预览对话框（逐模块勾选，显示「本机 X 条 → 文件 Y 条」）→ **逐个模块确认覆盖**（课表一次、便签一次、设置一次）→ 执行

**两种导出的文件格式完全一样**（只差 `modules` 里有几个键），所以「整体」和「单模块」共用同一段代码，解析只有一条路径 —— 没有两套逻辑要对齐。

文件是 UTF-8 的 JSON，直接用文本编辑器就能看和改：

```json
{
  "format": "stumate-backup",
  "schema": 1,
  "app": "StuMate-Android-Preview",
  "exportedAt": 1759200000000,
  "modules": {
    "courses":  { "count": 12, "items": [ { "id": 1, "title": "高等数学", "...": "..." } ] },
    "notes":    { "count": 7,  "items": [ "..." ] },
    "settings": { "advanceMinutes": 30, "themeMode": 0, "...": "..." }
  }
}
```

**为什么不引第三方库**：构建必须 `--offline`，拉不到 Gson / Moshi / kotlinx-serialization。所以自己写了约 200 行的 `MiniJson`（对象 / 数组 / 字符串转义 / 数字 / 布尔 / null 全覆盖），好处是**解析行为完全可控** —— 备份文件可能被用户手改，脏数据要尽量救而不是崩 —— 而且能直接在 JVM 上单测。

**解码一律「能救就救」**：单个条目缺关键字段（课程没标题、便签没内容）就跳过它，而不是让整份备份导入失败；认不出的模块名（新版本导出的文件拿到旧版本上导入）直接忽略，能读几个读几个。

**设置模块只收用户偏好**，不收 `first_run` / `last_tab` 这类「这台设备的当前状态」—— 备份出去再导到另一台机器上没有意义，还会把对方的界面打乱。导入设置后要**重启应用**才全部生效（主题攥在 Activity 手里，做一个半吊子的即时刷新反而更容易出错），这一点在 Toast 里说清楚了。

**5. 深色下的小字号不再用主色**

深色主色 `#1A73E8` 压在深色卡片上只有 3.8:1，做小字号会发闷。两处分别处理（**浅色模式都不变**，仍是主色）：

| 位置 | 浅色 | 深色 | 代码 |
|---|---|---|---|
| 今天页「接下来」的时间 | `#1A73E8` | **`#8AB4F8`** 浅色 Google Blue | `GoogleBlueLight` |
| 底部导航选中项文字 | `#1A73E8` | **白** | `selectedTextColor` |

- 时间用**提亮版**而不是纯白：纯白太素，和右侧课程名同色之后，时间就不像「时间」了；提亮版既保住品牌蓝、亮度也够。
- 导航选中项用白：那里已经有深蓝胶囊托着，白色最干净。
- `GoogleBlueLight` 是这一版新加在 `Theme.kt` 里的**命名色值** —— 深色下「需要品牌蓝、但字号小」的地方统一用它，不要再各自硬编码。

底部导航的**图标**仍是 `onPrimaryContainer`（深色 `#D3E3FD`），便签区的「全部」链接仍是主色。

**6. 问候语：34sp SemiBold → 38sp Light**

首屏那句「夜深了。」是唯一一句「有人味」的话。先加大到 **38sp**（Material 的 `displaySmall` 是 36sp，这里刻意压过一格），行高同步 42 → 46sp，顶栏内边距不动。

随即发现 38sp 配 SemiBold 偏笨重 —— 这个尺寸已经靠字号本身撑起气势了，字重于是改走 **Light**，更接近 Google 首屏那种「轻但醒目」的调子。

- **40sp 是上限**：「早上好。」四个字在 360dp 窄屏上就该折行了
- 实测：文字高 86px → **96px**（+12%），笔画墨量 **−25%**

**7. 顺手修掉的**

- `.gitignore` 的 `/build/` → `build/`：原写法只匹配根目录，`app/build/`（172M 编译产物）会跟着入库
- `ClassDao` 补 `deleteAll()`：覆盖导入课程表要先清空整表

**踩坑（值得记住）**：kapt 把 KDoc 转成 Java stub 时，**注释里的 `U+XXXX` 写法如果带反斜杠，会被 javac 当成 Unicode 转义解析**，报「非法的 Unicode 转义」——而且报错指向生成的 stub 文件，不是你的源码，第一次看很容易懵。KDoc 里提 unicode 转义要写成 `U+XXXX`。

**单测**：111 → **145 全绿**。新增 `MiniJsonTest`（16）与 `BackupCodecTest`（18）。

### v4.2 — 今天页便签摘要的 5 条上限 · Deadline 优先 · 深色表格底纹

M3 分支上的第三轮，四件事都围绕「今天页那几行便签摘要怎么读得更快」和「深色课表别糊成一片」。

**1. 便签最多在今天显示 5 条**

抽出纯函数 `data/TodayNotePicker.kt`：

```kotlin
object TodayNotePicker {
    const val TODAY_NOTE_LIMIT = 5
    fun pick(notes: List<NoteEntity>): List<NoteEntity> { … }      // 返回正文条
    fun needsMoreRow(notes: List<NoteEntity>): Boolean = notes.size > TODAY_NOTE_LIMIT
}
```

| 库中便签数 | 正文条数 | 「…」省略栏 | 合计栏位 |
|---|---|---|---|
| 0 | — | — | 0（整段不渲染） |
| ≤ 5 | 全部 | 无 | `n` |
| > 5 | 4 | 有 | **恒为 5** |

**为什么超量时只留 4 条正文**：正好 5 条填满时，用户没法判断「到底还有没有」。留一格给省略栏，这件事就从「数一数」变成「看有没有那一栏」—— 一眼可辨。代价是超量时只看得到 4 条，但摘要区本来就不是用来看全的（旁边有「全部」入口）。

**2. Deadline 类事件优先显示**

```kotlin
val ordered = notes.sortedBy { if (it.hasDeadline) 0 else 1 }
```

`sortedBy` 是**稳定排序**，同组内保持用户拖拽顺序，所以「急事上浮」和「我排的顺序别乱」两件事不冲突。

`hasDeadline` 同时要求 `typeIndex` 属 Deadline 类 **且** `deadlineAt != null` —— 只选了分类却没填时刻的条目不算优先，因为倒计时画不出来，提上来也只是一句没有信息量的标题。

**3. 省略栏是同格式的灰色栏位**

不是另做一种控件，而是**逐项复刻** `NoteSummaryRow` 的几何（`padding(horizontal = 14.dp, vertical = 12.dp)`、竖线 `3.dp × 18.dp` + `RoundedCornerShape(2.dp)`、`Spacer(11.dp)`），只换三处颜色：

| 元素 | 正文行 | 省略栏 |
|---|---|---|
| 底色 | `surface` | `surfaceVariant.copy(alpha = 0.4f)` |
| 竖线 | 便签 accent 色 | `outlineVariant` |
| 文字 | `onSurface` | `onSurfaceVariant`（内容为「…」） |

|---|---|---|---|

| 纵向列分隔 | `0.05` | **`0.09`** | `GRID_COLUMN_ALPHA` / `_DARK` |

**为什么深色要单独一套值**：底纹靠 `onSurface` 叠色实现。浅色主题里 `onSurface` 近黑，压在白底上是「深灰压白」；深色主题里它近白，压在近黑底上是「浅灰提黑」—— 同样 alpha，后者感知上弱得多。所以深色不是「也调 0.03」，而是给一组略高的值让两边的**观感**对齐，而不是让**数值**对齐。

`clickable(onClick = {})` 只吃掉点击语义（保证无障碍焦点与水波纹），真正的判定交给 `pointerInput(cls.id) { detectTapGestures(...) }`：`onTap` → `onSelect()`，`onDoubleTap` → `onEdit()`，`onPress` 手动 `emit(PressInteraction.Press)` / `Release` 让按下态动画照常。单击与双击由 Compose 内置的双击窗口区分，不需要自己攒计时器。

**高亮提前到 `onPress`（第一次点下就亮）**

`onTap` 要等双击判定窗口关闭（约 300ms）才回调，那段时间里块是「没反应」的 —— 手感很木。所以把 `onSelect()` 也放进 `onPress`：**手指按下的当帧就高亮，单击和双击共用这一次高亮**。因为 `onSelect` 是幂等的（只写 `selectedClassId`），之后 `onTap` 再亮一次也没有副作用。

**2. 色条按「是否今天」分流**

`GridCell` 新增 `isToday` 与 `selected` 两个参数，并引入 `selectColor`：

- **今日**（`isToday == true`）→ `primary`，蓝
- **非今日**（深色主题）→ `surfaceVariant`；（浅色主题）→ `outlineVariant`，灰

左侧竖色条选中时从 2dp 加粗到 `HL_BAR_WIDTH`（4dp）并转成纵向渐变；临时课的暖黄条也在选中时让位给蓝/灰。描边、光晕、底色全部跟着 `selectColor` 走 —— 非今日选中**不再染蓝**。

**3. 选中态的四层表达**

| 层 | 未选中 | 选中（今日 / 非今日） |
|---|---|---|
| 左侧色条 | 2dp，主色 α0.55（临时课=暖黄） | 4dp，蓝 / 灰 + 纵向渐变 |
| 卡片描边 | `0.75dp`，outline α0.40 | `1.5dp`，selectColor α0.80 |
| 卡片底色 | `surface`（临时课 = `secondaryContainer`） | selectColor α0.12（浅）/ 0.22（深） |
| 光晕 | 无 | 向外 3dp，α0.17（浅）/ 0.30（深） |

另加 `scale = 1.05` 的原地放大（用 `graphicsLayer`，不参与布局、不挤开邻居）。**光晕用 `selectColor` 而不是 `shadow`** —— 阴影是灰的、跟主题无关，光晕取自主色/选中色才能深浅主题都融入，且非今日自动变灰。

**4. 一致性与取舍**

- 单击**已选中**的块：保持选中，不 toggle 掉（浏览时手抖不会丢焦点）
- 双击必然先触发一次单击，因此 `onSelect` 必须是**幂等**的——它只设 `selectedClassId`，无副作用
- 点网格空白处取消选中：在网格底层挂一个 `detectTapGestures`，它用 `awaitFirstDown(requireUnconsumed = true)`，课程块已消费的 down 不会再传过来，所以**只会接住「落在底纹/列间空白上」的点击**
- 键盘暂不处理（用户决策），`clickable` 已保留 Enter/Space 的语义通道
- **高亮零延迟**：第一次按下的当帧就高亮（走 `onPress`），不等双击窗口。
  代价是「双击时高亮会先亮一次」——但这本来就是同一个块的选中态，
  `onSelect` 幂等，视觉上无跳变

`SHAPE_SMALL_RADIUS = 8.dp`（供光晕的 `CornerRadius` 复用，避免 `SHAPE_SMALL` 的圆角值写两遍）。

### v3.15 — 课表高亮的视觉层级与主题自适应

v3.14 把高亮线条做「精致」了，但**层级没做**：全屏只有「亮 / 不亮」两种状态，而且几何与透明度是写死的，浅色下能看清、深色下就打折。这一版把高亮做成一整套分级语言，并让每一档都与主题绑死。

**1. 四级强度，收敛成一条进度**

一屏里其实同时存在好几种「亮着」，原来它们看起来都差不多：

| 状态 | 原来的样子 | 现在的样子 |
|---|---|---|
| 今天那一列 | 竖条 + 主色描边 | **弱**：竖条 α0.30 / 0.56×宽，描边只有淡淡一层 |
| 鼠标悬停 | 无 | **中**：描边亮起、卡片轻抬，点之前就知道会选中谁 |
| 手指按住 | 无 | 描边再亮一档 |
| 手动选中 | 竖条渐变 + 光晕 + 混合底 | **强**：1.6dp 主色实线 + 外光晕 + 抬 3dp |
| 正在上课 | 无 | 独立一支：小圆点 + 柔光晕，和时间维度绑定，与「选中」可以并存 |

关键是这五档**不是五套样式**，而是同一条 0 → 1 进度上的刻度（`maxOf` 取最强档，不叠加）。所以状态互相切换是平滑滑动，不会「叠出第六种颜色」。分级收在 `HighlightSpec.of()` 一处，调参只改一个函数。

**2. 对比度：浅色 / 深色分别标定，不再共用一套 α**

原来 `primaryContainer` 混合 72%、光晕 α0.14、描边 α0.07 —— 这些值在浅色下勉强能用，在深色下全都失效：

- **描边**：`onSurface α0.07` 对白卡片只有 **1.05:1**，等于没画。浅色改用主题的 `outline`（`#B4BBC5` → `#9AA3AF`，对白色 1.76:1）
- **深色下不能用灰**：`onSurface`(浅灰) 与 `surface`(深灰) 只差 1.78:1，在深底上「悄悄出现一条灰线」根本看不见。所以深色改走**主色 + 逐级透明度**
- **光晕** α0.14 → 浅色 0.17 / 深色 **0.30**（深背景上要更亮才压得住）
- **容器色**深色混合比例 0.72 → **0.88**（`primaryContainer` 本身太暗，混 72% 几乎看不出亮）
- **标题色**深色下**只轻微**向 `onPrimaryContainer` 靠拢（0.55）：深色主题的 `onPrimaryContainer` 是 `#D6E4FF`，靠过去反而**变亮**、与底色对比不升反降 —— 改成靠底色变深来拉开
- 列高亮底色也分主题：浅色 α0.055 / 深色 α0.14

**3. 统一到一个函数，顺手消掉重复代码**

`drawHighlightLines` 从 10 个散参数改成收一个 `HighlightLines` 对象（竖条 / 描边 / 光晕各带自己的颜色与宽度），便签行与课表卡片从此共用同一份几何规范 —— 两个列表的色条落在同一条线上。

同时删掉了 v3.14 遗留的**重复定义**（`drawHighlightLines` 与 `HL_*` 常量各被写了两遍）和已无人调用的 `Modifier.pressable`。

**4. 动效**

- **进 / 出非对称**：亮起 280ms、收回 180ms。取消选中是「撤销」，不该拖泥带水
- **悬停 120ms**：只要跟手，不做表演。用 `MutableInteractionSource` 同时喂「悬停」与「按下」，两档反馈同源，不会自相矛盾
- **课表格子**：格宽只有 40~76dp，反馈必须轻 —— 0.5px 描边 + 1dp 抬升 + 2% 按下缩放，粗了会糊成一团

表格里的课程块**没有**加选中高亮。格子小、块上文字已占满，再叠描边和光晕会盖住信息本身 —— 保留 hover / press 的即时反馈即可。高亮语言只用在有空间承载它的列表卡片上。

### v3.12 — 主界面切换的帧率

v3.8 给顶部栏加的「切页时折叠」动画，是切页掉帧的元凶。

**根因：顶栏高度一动，整屏每帧换一套约束**

`Scaffold` 的 `contentPadding.top` 是**直接取顶栏的测量高度**的（`Scaffold.kt` 里
`if (topBarPlaceables.isEmpty()) insets.calculateTopPadding() else topBarHeight`）。
所以 `expandVertically` / `shrinkVertically` 每改一次高度，内容区的约束就变一次：

- 课表 `WeekGrid` 的 `BoxWithConstraints` 读到新的 `maxHeight` → **每帧重新组合**，列宽、行高、`gridHeight` 全部重算，所有课程块重新定位
- 每个课程块的 `Card` 高度跟着变 → 块内 `Text` 的 `maxHeight` 约束每帧都在变。而文字布局缓存的 key 里带 `constraints`（`TextLayoutHelper.canReuse`，`softWrap || overflow == Ellipsis` 时会比较 `maxHeight`），**于是每帧对每个块重新排版一次文字**

一次切页 240ms ≈ 14 帧，每帧都在做上面这些事 —— 帧率自然塌。

**改法**

1. **顶栏不再做高度动画**，跟着内容一起瞬时切换（`AnimatedVisibility` → 普通 `if`）。代价是没有折叠动画；好处是整屏约束恒定，进来之后一次排完就不再动
2. **Tab 内容过渡改用 `ExitTransition.None`**，旧页面立刻退场：
   - 过渡期间只需绘制一层页面，不用同时画两屏（课表那屏内容很重）

### v3.11 — 选中项原地放大 + 动画收敛

**1. 便签 / 课表列表：选中项「独立扩大」**

### v3.10 — 选中动画的性能

v3.9 让「选中放大」真正动起来了，但代价是**动画期间每一帧都在重组整张网格**，帧率不好看。这一版把每帧的开销压下去，**动画效果和时长完全不变**。

**根因：每帧都在做大量无谓的工作**

1. **`GridCell` 每帧都在重组** —— 它的 `onClick` 是外层每帧新建的闭包（捕获了每帧新建的 `Placed`），参数永远不相等，跳过重组直接失效。于是每个块每帧都要重跑 4 个 `animate*AsState`、`Card`/`Surface`、若干 `Text`，还带一次 `BoxWithConstraints` 子组合。
2. **`BoxWithConstraints` 满天飞** —— `DayColumn`（7 个）+ `GridCell`（每个块 1 个）里各有一个，而 `SubcomposeLayout` 在内容 lambda 变化时会重跑子组合。内容 lambda 每帧都是新的 → 每帧白跑几十次子组合。
3. **每帧都在分配** —— `classes.filter { it.dayOfWeek == day }` × 7、左侧刻度列表重建、`busyDays` 重建。
4. **组合跑两遍** —— `mapping` 在 `BoxWithConstraints` **外面**算，于是每帧先重组一遍 `WeekGrid` 本体，再因子组合 lambda 变化重跑一遍网格内容。
5. **常驻图层** —— `Modifier.pressable` 给每个块常驻一层 `graphicsLayer`；`Modifier.alpha(1f)` 也给刻度文字常驻一层。
6. **永不停止的动画** —— 状态圆点的「呼吸」用 `rememberInfiniteTransition`，让 App 一帧都闲不下来。

**改法**

- `GridCell` 参数全部做成「跨帧稳定」：`onClick` 收 `ClassEntity`（不再收闭包）；块高**不再传原始值**，改成传 `showRoom` / `showDetails` 两个布尔（它们只在跨过 46dp / 76dp 阈值时才变），于是绝大多数帧 `GridCell` 直接跳过重组
- 删掉 `DayColumn` 和 `GridCell` 里的 `BoxWithConstraints`：列宽由调用方传 `columnWidth`，块高阈值由调用方算好
- `byDay`（按天分组）、`days`（有课的天）、`marksNow`（左侧刻度）全部 `remember` 住
- `mapping` 的读取点挪进 `BoxWithConstraints` 内部 —— 每帧被失效的只剩网格这一层子组合，`WeekGrid` 本体不再跟着重组（组合从两遍降到一遍）
- `Modifier.pressable` 只在真的按下时才挂 `graphicsLayer`；刻度文字的 `alpha` 只在小于 1 时才挂图层
- **去掉状态圆点的呼吸动画**（保留颜色过渡）。这是唯一一条永不停止的动画，代价是 App 永远进不了空闲状态

**没有改的**：动画时长、缓动、视觉效果一律不变。块高每帧变化导致的文字重新排版仍然存在——但 `MultiParagraphIntrinsics` 是缓存的，单行短文本的实际开销很小，实测不值得为它牺牲「矮块省略号截断」的现有行为。

assembleDebug 成功，单测 46 个全绿（27 + 5 + 9 + 5）。

### v3.9 — 课表选中高亮的动画（补齐 v3.8 漏掉的两处）

v3.8 给课表加的是**颜色类**过渡（底色 / 描边 / 文字色），但真正最显眼的「选中变大」是**几何跳变**——没动。这一版把几何也接上动画。

**1. 选中课程 → 时间轴放大（原来瞬间切换）**

- 根因：`TimeAxis.mappingOf(span, focus)` 里 focus 是个**开关**——`share` 直接从「原始占比」跳到 `×2.2`（带上限）。所以选中一门课时，整列的课程块、横线、左侧刻度会一起瞬移。
- 改法：`mappingOf` 增加 `progress: Float = 1f` 参数，`share = base + (full - base) × progress`。
  **关键性质**：`progress = 0` 时 `share` 恰好等于 `base`，此时 `focusPerMinute` / `otherPerMinute` 都回到 `1 / span.minutes`，分段映射**精确退化成线性**——所以动画的起点就是「没选中」的样子，中间每一帧都是合法的映射，不会出现块和刻度对不上的情况。
- UI 侧用 `Animatable` 推 `progress`：0 → 1 展开、1 → 0 收回。**直接换一门课（A → B）时先收回到 0 再展开 B**，避免焦点瞬移（收完时 progress = 0，映射是线性的，换焦点那一刻正好接得上）。
- 顺带：`heldFocus` 记住「当前正在放大的那一段」，取消选中后它还在，收起动画才知道往回收什么。
- 单测 22 → 27 个：`progress = 0` 与线性映射逐分钟相等、中间值插值、越界夹取、任意 progress 下仍单调、放大占比随 progress 单调不减。

**2. 点列头换高亮 → 刻度与横线交叉淡入淡出（原来瞬间换一套）**

- 左侧刻度会从「等距固定间隔」换成「那一天各事项的起止时刻」，横线同步。原来整套刻度是瞬间替换的。
- 改法：横线从「每列各画一段」提到**一层铺满整个网格宽度**的底层（顺便消除了列与列之间 1dp 的断缝），和左侧刻度一起按 `axisMarks` / `axisMarksPrev` + `axisCross` 两个 alpha 交叉淡入淡出。线和标签始终共用同一份时刻，所以永远对得上。
- 交叉进度用「步进计数」表达：`axisStep` 每次换刻度 +1，`axisProgress` 从 k 涨到 k+1，减掉 k 就得到 0 → 1。用 `LaunchedEffect` 而不是在组合期写状态——换刻度那一帧 `axisCross` 还是 1（旧的一套满的），晚一帧更新不会闪。
- `DayColumn` 不再自己画横线（只留高亮底色），`timeMarks` 参数随之去掉。

assembleDebug 成功，单测 **46 个**全绿（27 + 5 + 9 + 5）。

## 如何运行

1. 在 Android Studio 中打开此项目。
2. 等待 Gradle 导入完成并构建。
3. 在 Android 设备或模拟器上运行（最低 Android 5.0，目标 Android 14）。

> **构建环境**：本项目锁定 **Gradle 8.4 + JDK 17**（AGP 8.1.1 与 Gradle 9.x 不兼容，会报 `NoSuchMethodError: DependencyHandler.module`；JDK 21 下 kapt 会报 `module jdk.compiler does not export com.sun.tools.javac.main`）。依赖已缓存，可加 `--offline` 离线构建。
