# ClassReminder — Android 课程提醒 App

一个 Android 课程提醒应用，使用 **Kotlin + Jetpack Compose + Room + Foreground Service** 构建。

## 功能

- **快速便签** — 首页是随手记的便签列表：点「+」新增（默认置顶；若已高亮选中某条则插到它上方），单击选中高亮、左下角浮出编辑 / 删除，点空白处取消选中；长按整栏上下拖动排序（拖动时略微放大并抬起阴影）；左滑露出编辑按钮、大幅左滑直接滑出删除；「回撤」按钮（纯图标，与加号按钮同尺寸对齐）可撤销上一次操作
- **课程管理** — 添加 / 编辑 / 删除每周课程，数据持久化到 Room 数据库
- **智能提醒** — 前台 Service 每 30 秒轮询，课程即将开始或正在上课时发送高优先级通知
- **锁屏弹窗** — 可选全屏锁屏弹窗（LockOverlayActivity），不错过每一节课
- **周课表** — 底部栏切换「便签」和「课表」两种视图，课表支持表格 / 列表两种模式；右下角加号上方有**查看 / 编辑模式切换**（默认查看：眼睛图标，点课程只高亮选中并展开详情、不弹编辑框；点一下切编辑：铅笔图标，点课程直接进编辑对话框）；表格纵轴按**真实时间比例**（从本周最早一节课开始、随屏幕高度自适应），**点列头可高亮任意一天**——高亮列会加宽、左侧刻度换成那一天各事项的起止时刻；再点一次列头取消全部高亮，左侧退回等距的固定间隔；今天那一列的表头带「今日」角标（与手动高亮无关）
- **动态前台通知** — 前台通知实时显示检测状态：正在上课/即将上课/今日课程概况
- **浅色/深色主题** — 三种模式：跟随系统、浅色、深色，设置页一键切换
- **开机自启** — 可开启开机自动启动提醒服务
- **自定义图标** — 支持启动器图标和通知栏图标

## 架构

```
MainActivity (单 Activity)
  └─ ClassReminderTheme (浅色/深色支持)
       └─ Surface + Scaffold
            ├─ TopAppBar × 底部导航栏（便签 / 课表 / 设置）
            ├─ NoteListView (快速便签：选中高亮 / 拖动排序 / 左滑 / 回撤)
            ├─ WeekView (表格 / 列表两种模式，按周分组)
            └─ SettingsPage (主题、权限、提醒设置)
  └─ MainViewModel ──→ Room Database
  └─ ClassReminderService (Foreground Service，每 30 秒轮询)
       └─ LockOverlayActivity (锁屏弹窗)
  └─ BootReceiver (开机自启)
```

### v3.13 — 主界面切换回退到无过渡

v3.8 起给「主界面之间的切换」加的那些过渡，优化了几轮仍然明显卡顿，按用户要求**整体回退**：主界面之间现在是瞬时切换，没有任何过渡动画。

**回退内容**

- **内容区**：`AnimatedContent`（新页面淡入 + 横向位移）→ 回到普通 `when (selectedTab)`
- **顶部栏**：v3.12 已经改回普通 `if (selectedTab == 0)`（不做高度动画），本次保持
- **悬浮按钮**：外层 `AnimatedVisibility(selectedTab != 2)`（缩放淡入淡出）+ 模式切换按钮的 `AnimatedVisibility(selectedTab == 1)` → 回到普通 `if / else` 分支

**保留未动的**

以下都不属于「主界面之间的切换」，仍然保留动画：便签 / 课表的选中高亮与原地放大、加号展开菜单、查看 / 编辑模式切换、搜索框开合、周次切换、表格 ↔ 列表、每天折叠、左下角操作区、按钮按下反馈。

**切页为什么不适合叠过渡**

切一次页本身就要组合出新的一屏，而课表那屏很重（7 列 × 若干课程块 + 左侧刻度 + 表头）。在这一帧上再叠加淡入 / 位移 / 交叉淡入，等于把最重的一帧挤得更满 —— 过渡越"好看"，这一帧越容易掉。所以这类"整屏替换"的场景，要么内容本身够轻，要么就别加过渡。

assembleDebug 成功，单测 46 个全绿（27 + 5 + 9 + 5）。

### v3.12 — 主界面切换的帧率

v3.8 给顶部栏加的「切页时折叠」动画，是切页掉帧的元凶。

**根因：顶栏高度一动，整屏每帧换一套约束**

`Scaffold` 的 `contentPadding.top` 是**直接取顶栏的测量高度**的（`Scaffold.kt` 里
`if (topBarPlaceables.isEmpty()) insets.calculateTopPadding() else topBarHeight`）。
所以 `expandVertically` / `shrinkVertically` 每改一次高度，内容区的约束就变一次：

- 课表 `WeekGrid` 的 `BoxWithConstraints` 读到新的 `maxHeight` → **每帧重新组合**，列宽、行高、`gridHeight` 全部重算，所有课程块重新定位
- 每个课程块的 `Card` 高度跟着变 → 块内 `Text` 的 `maxHeight` 约束每帧都在变。而文字布局缓存的 key 里带 `constraints`（`TextLayoutHelper.canReuse`，`softWrap || overflow == Ellipsis` 时会比较 `maxHeight`），**于是每帧对每个块重新排版一次文字**

一次切页 240ms ≈ 14 帧，每帧都在做上面这些事 —— 帧率自然塌。

**改法**

1. **顶栏不再做高度动画**，跟着内容一起瞬时切换（`AnimatedVisibility` → 普通 `if`）。代价是没有折叠动画；好处是整屏约束恒定，进来之后一次排完就不再动
2. **Tab 内容过渡改用 `ExitTransition.None`**，旧页面立刻退场：
   - 过渡期间只需绘制一层页面，不用同时画两屏（课表那屏内容很重）
   - 顶栏是瞬时切换的，旧页面会因此重排一次；立刻退场就看不到那一下跳动
   - 新页面保留淡入 + 轻微横移（`fadeIn` + `slideInHorizontally`），仍有明确的方向感

顺带确认：`Scaffold` 在「顶栏槽位没有内容」时会自动改用状态栏内边距，所以便签页有顶栏、其它页没有时，两边的顶部留白都是对的，不需要额外处理。

assembleDebug 成功，单测 46 个全绿（27 + 5 + 9 + 5）。

### v3.11 — 选中项原地放大 + 动画收敛

**1. 便签 / 课表列表：选中项「独立扩大」**

单击高亮后，被选中的那一条会原地放大到 **1.05 倍**并抬起阴影，画面重心立刻落到它身上。

- 用 `graphicsLayer` 缩放实现，**它不参与布局** —— 所以是「自己长大」而不是把上下两条挤开，也不需要重排文字，比改尺寸便宜得多
- 放大后要盖住相邻条目，否则下半截会被下一条压住：便签行按「拖动 > 选中 > 普通」排 `zIndex`，课表卡片选中时 `zIndex(1f)`
- 1.05 是上限而不是随手取的：便签行左右各留 12dp（行宽约 336dp）、课表卡片左右各留 10dp（卡宽约 340dp），再大一点卡片就会被列表内边距裁掉

**2. 动画收敛：一个条目只跑一条动画**

原来便签行选中时要跑 **6 条**独立动画（色条 / 底色 / 文字色 / 描边色 / 描边粗细 / 阴影），课表卡片和表格里的课程块各 4 条。每条 `animate*AsState` 都是独立的一路动画，各自逐帧失效重组。

现在改成**一条 0 → 1 的进度**（`rememberSelectionProgress`），底色、色条、文字色、描边颜色与粗细、阴影、放大倍数全部由它 `lerp` 出来：

- 一个条目只跑一路动画，条目一多帧数也不会塌
- 各属性天然同步 —— 原来六条动画时长一样但各自启动，观感上会有细微的「错拍」
- 便签行 6 → 1（阴影因拖动还要单独一条），课表卡片 4 → 1，表格课程块 4 → 1

**3. 顺带削掉的复杂度**

- 按下反馈的规格由 `spring` 换成 **120ms 的 tween**：弹簧会来回震荡好几帧，帧数不好预测
- 课程块详情淡入去掉 60ms 延迟（少一个待触发的动画）

动画时长与缓动沿用 `ENTER_MS` / `EXIT_MS`，视觉风格未变。

assembleDebug 成功，单测 46 个全绿（27 + 5 + 9 + 5）。

### v3.10 — 选中动画的性能

v3.9 让「选中放大」真正动起来了，但代价是**动画期间每一帧都在重组整张网格**，帧率不好看。这一版把每帧的开销压下去，**动画效果和时长完全不变**。

**根因：每帧都在做大量无谓的工作**

1. **`GridCell` 每帧都在重组** —— 它的 `onClick` 是外层每帧新建的闭包（捕获了每帧新建的 `Placed`），参数永远不相等，跳过重组直接失效。于是每个块每帧都要重跑 4 个 `animate*AsState`、`Card`/`Surface`、若干 `Text`，还带一次 `BoxWithConstraints` 子组合。
2. **`BoxWithConstraints` 满天飞** —— `DayColumn`（7 个）+ `GridCell`（每个块 1 个）里各有一个，而 `SubcomposeLayout` 在内容 lambda 变化时会重跑子组合。内容 lambda 每帧都是新的 → 每帧白跑几十次子组合。
3. **每帧都在分配** —— `classes.filter { it.dayOfWeek == day }` × 7、左侧刻度列表重建、`busyDays` 重建。
4. **组合跑两遍** —— `mapping` 在 `BoxWithConstraints` **外面**算，于是每帧先重组一遍 `WeekGrid` 本体，再因子组合 lambda 变化重跑一遍网格内容。
5. **常驻图层** —— `Modifier.pressable` 给每个块常驻一层 `graphicsLayer`；`Modifier.alpha(1f)` 也给刻度文字常驻一层。
6. **永不停止的动画** —— 状态圆点的「呼吸」用 `rememberInfiniteTransition`，让 App 一帧都闲不下来。

**改法**

- `GridCell` 参数全部做成「跨帧稳定」：`onClick` 收 `ClassEntity`（不再收闭包）；块高**不再传原始值**，改成传 `showRoom` / `showDetails` 两个布尔（它们只在跨过 46dp / 76dp 阈值时才变），于是绝大多数帧 `GridCell` 直接跳过重组
- 删掉 `DayColumn` 和 `GridCell` 里的 `BoxWithConstraints`：列宽由调用方传 `columnWidth`，块高阈值由调用方算好
- `byDay`（按天分组）、`days`（有课的天）、`marksNow`（左侧刻度）全部 `remember` 住
- `mapping` 的读取点挪进 `BoxWithConstraints` 内部 —— 每帧被失效的只剩网格这一层子组合，`WeekGrid` 本体不再跟着重组（组合从两遍降到一遍）
- `Modifier.pressable` 只在真的按下时才挂 `graphicsLayer`；刻度文字的 `alpha` 只在小于 1 时才挂图层
- **去掉状态圆点的呼吸动画**（保留颜色过渡）。这是唯一一条永不停止的动画，代价是 App 永远进不了空闲状态

**没有改的**：动画时长、缓动、视觉效果一律不变。块高每帧变化导致的文字重新排版仍然存在——但 `MultiParagraphIntrinsics` 是缓存的，单行短文本的实际开销很小，实测不值得为它牺牲「矮块省略号截断」的现有行为。

assembleDebug 成功，单测 46 个全绿（27 + 5 + 9 + 5）。

### v3.9 — 课表选中高亮的动画（补齐 v3.8 漏掉的两处）

v3.8 给课表加的是**颜色类**过渡（底色 / 描边 / 文字色），但真正最显眼的「选中变大」是**几何跳变**——没动。这一版把几何也接上动画。

**1. 选中课程 → 时间轴放大（原来瞬间切换）**

- 根因：`TimeAxis.mappingOf(span, focus)` 里 focus 是个**开关**——`share` 直接从「原始占比」跳到 `×2.2`（带上限）。所以选中一门课时，整列的课程块、横线、左侧刻度会一起瞬移。
- 改法：`mappingOf` 增加 `progress: Float = 1f` 参数，`share = base + (full - base) × progress`。
  **关键性质**：`progress = 0` 时 `share` 恰好等于 `base`，此时 `focusPerMinute` / `otherPerMinute` 都回到 `1 / span.minutes`，分段映射**精确退化成线性**——所以动画的起点就是「没选中」的样子，中间每一帧都是合法的映射，不会出现块和刻度对不上的情况。
- UI 侧用 `Animatable` 推 `progress`：0 → 1 展开、1 → 0 收回。**直接换一门课（A → B）时先收回到 0 再展开 B**，避免焦点瞬移（收完时 progress = 0，映射是线性的，换焦点那一刻正好接得上）。
- 顺带：`heldFocus` 记住「当前正在放大的那一段」，取消选中后它还在，收起动画才知道往回收什么。
- 单测 22 → 27 个：`progress = 0` 与线性映射逐分钟相等、中间值插值、越界夹取、任意 progress 下仍单调、放大占比随 progress 单调不减。

**2. 点列头换高亮 → 刻度与横线交叉淡入淡出（原来瞬间换一套）**

- 左侧刻度会从「等距固定间隔」换成「那一天各事项的起止时刻」，横线同步。原来整套刻度是瞬间替换的。
- 改法：横线从「每列各画一段」提到**一层铺满整个网格宽度**的底层（顺便消除了列与列之间 1dp 的断缝），和左侧刻度一起按 `axisMarks` / `axisMarksPrev` + `axisCross` 两个 alpha 交叉淡入淡出。线和标签始终共用同一份时刻，所以永远对得上。
- 交叉进度用「步进计数」表达：`axisStep` 每次换刻度 +1，`axisProgress` 从 k 涨到 k+1，减掉 k 就得到 0 → 1。用 `LaunchedEffect` 而不是在组合期写状态——换刻度那一帧 `axisCross` 还是 1（旧的一套满的），晚一帧更新不会闪。
- `DayColumn` 不再自己画横线（只留高亮底色），`timeMarks` 参数随之去掉。

assembleDebug 成功，单测 **46 个**全绿（27 + 5 + 9 + 5）。

### v3.8 — 全局动效：所有切换与点击

保持原有配色 / 形状 / 间距不变，只补上过渡与反馈。时长与手感统一收在 `MainScreen.kt` 顶部的 `ENTER_MS`（240ms 入场）/ `EXIT_MS`（160ms 出场）两个常量里，缓动沿用 `tween` 默认的 `FastOutSlowInEasing`。

**切换类**

- **底部 Tab 切换** — 内容用 `AnimatedContent` 做淡入淡出 + 顺着 Tab 顺序的横向位移（往右切从右侧进）
- **顶栏** — 只有便签页有顶栏，切走时向上折叠淡出，切回来再展开
- **搜索框开关** — 标题 ↔ 输入框、放大镜 ↔ 关闭图标，各自交叉淡入 + 缩放（图标锚点放在左端）
- **表格 ↔ 列表** — 保留原有横移过渡，时长并入统一常量
- **换周** — 新增：整屏横向滑过，方向跟着「上一周 / 下一周」。过渡目标里带上了周次，**滑动中的旧页面显示的是「它自己那一周」的内容**（各自按自己的周次过滤）
- **查看 / 编辑模式** — 按钮底色与图标色渐变过渡，眼睛 ↔ 铅笔交叉淡入缩放
- **加号展开菜单** — 从加号那一侧向上展开 / 收起（`expandVertically` / `shrinkVertically`），图标加号 ↔ 关闭交叉淡入
- **课表列头点选高亮** — **逐列**做宽度动画（每列从它自己上一次的宽度过渡，高亮开 / 关两个方向都不跳）、高亮底色淡入淡出、星期文字颜色渐变
- **列表模式折叠某天** — 高度展开 / 收起 + 淡入淡出，箭头改成**旋转 180°**（不再来回换两个图标）
- **便签选中态 / 课程块选中态 / 左下角操作区 / 空状态** — 全部改为渐变与淡入淡出

**点击类**

- **新增 `Modifier.pressable()`** — 统一的点按反馈：保留系统水波纹（`indication` 取当前 `LocalIndication`），按下时整块缩到 0.97、松手用 `spring` 弹回。已应用到便签卡片、课程块、列表卡片、两个方块按钮
- **FAB 类按钮**（主加号、回撤、左下角编辑 / 删除、左滑露出的编辑按钮）通过 `FloatingActionButton(interactionSource = ...)` 复用同一套按下缩放
- **主题单选行** — 选中的那一行铺一层淡主色，切换时淡入淡出
- **服务状态圆点** — 颜色过渡 + 运行中时轻微呼吸（`rememberInfiniteTransition`）

**踩到的两个坑**

- Compose 1.6 里**没有** `rotateIn` / `rotateOut`（只有 `scaleIn` / `scaleOut` / `slideIn*` / `expand*` / `fade*`），旋转只能用 `Modifier.graphicsLayer { rotationZ = ... }` 自己驱动
- `graphicsLayer` 的缩放只作用于**它之后**（更内层）的节点。所以按下缩放要挂在组件的外层 modifier 上 —— 比如 `FabTile` 一开始挂在内部 `Column` 上，结果只缩了图标和文字、卡片底不动；同理 `.clip().background()` 之前必须先 `graphicsLayer`

### v3.7 — 去掉选中块的自调尺寸

- **课程块高度只由时间轴决定** — 上一版在分段线性放大之外，又给选中块加了「至少 +40dp / 不低于 104dp」的高度下限，两套机制叠加会让块和它自己的时间刻度对不上、尺寸也不可预测（这就是显示大小 bug 的来源）。现在全部移除
- 一并删掉 `EXPAND_EXTRA`、`SELECTED_BLOCK_MIN_HEIGHT`、`GRID_EXPANSION_ROOM`，以及"选中时整行加高 120dp"的临时逻辑
- `GridCell` 的选中/未选中两条分支合并成一条：尺寸交给外层，内部只按格高决定显示几行内容

### v3.6 — 时间轴分段线性：放大选中时段

- **换思路：不再挤别的块腾地方，而是把时间轴本身变成分段线性** — 选中某门课时，它的时段在纵轴上放大 `FOCUS_SCALE = 2.2` 倍（上限占整轴 `MAX_FOCUS_SHARE = 62%`），其余时段按剩余比例等比例压缩，**总高度不变**。所以「变大」非常直观，代价只是别的时段略微变矮
- **绝不缩小** — 放大后的占比用 `coerceAtMost(上限)` 再 `coerceAtLeast(原始占比)`：既不会被上限压到比原来还小，也**不会因为 `coerceIn(base, MAX)` 在 `base > MAX` 时抛异常而崩溃**
- **左侧刻度与格线跟着变形** — 它们和课程块共用同一个映射，所以标签、格线、块边界始终对齐
- **列宽配合加宽** — 高亮列系数 1.18 → 1.35
- `TimeAxis` 新增 `Mapping` / `Focus` / `mappingOf`；`layout` 改为接收映射而不是裸 span
- **单测从 15 个补到 22 个** — 覆盖线性退化、放大占比、上限夹取、占比不得低于原始值（原崩溃点）、单调性、以及映射下的布局
