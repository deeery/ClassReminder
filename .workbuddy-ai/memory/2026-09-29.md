## 通读 ClassReminder 项目（Android 课程提醒 App）

完整读完全部源码（18 个 .kt，共 3567 行）。项目结构与关键点：

- 技术栈：Kotlin 1.9.20 + Jetpack Compose（BOM 2024.01.00）+ Room 2.6.1 + 前台 Service；AGP 8.1.1，compileSdk/targetSdk 34，minSdk 21，jvmTarget 1.8。
- 入口：`MainActivity`（单 Activity，Compose）→ `MainScreen`（列表/课表/设置三 Tab，底部导航）。ViewModel 走 `MainViewModel`，数据落 Room（`AppDatabase` v4，库名 class_reminder_db）。
- 后台：`ClassReminderService` 前台服务，`scheduleWithFixedDelay` 首次 5s、之后每 30s 轮询；`checkAndNotify()` 查 DB → 更新前台通知 + 发高优先级提醒（渠道 class_reminder_alerts_v2，震动不响铃）+ 可选全屏 `LockOverlayActivity`。用 `lastShownId` 去重（内存态，重启会重发）。
- 数据模型 `ClassEntity`：id/title/dayOfWeek/startTime/endTime/room/notes/teacher/weeks/date。`date` 非空 = 一次性临时提醒。
- 纯逻辑工具（可单测）：`TodaySchedule`（今天课、剩余、跨零点处理）、`WeekSchedule`（周次文本解析，支持 `1-16周`/`第6周`/单双周，解析不出=不限制）、`TimetablePdfParser`（自研 PDF 解析：Inflater 解 FlateDecode + Tm/Tj 坐标提取 + UCS-2 解码，不引三方库）。
- 设置 `Prefs`：提前分钟(1~180 夹取)、开机自启、锁屏弹窗、主题模式、周次校准(week1_monday)、上次 Tab、课表显示模式。
- 主题 `ui/Theme.kt`：Light/Dark 两套 M3 配色；`ui/RomGuide.kt`：ColorOS/OPPO 系特有权限跳转（无标准 API，带兜底）。
- debug 变体有 `.test` 后缀包名，可与正式版共存。
- 测试：`WeekScheduleTest`、`TodayScheduleTest`、`TimetablePdfParserTest`（用真实 example.pdf 断言 15 个课程格）。

### 通读时发现的潜在问题（未改动，供后续参考）
1. `AppDatabase` 有 2→3、3→4 迁移，但缺 1→2；配合 `fallbackToDestructiveMigration()`，从 v1 升级会清库。
2. `MainViewModel.insertAll` 用 `currentTimeMillis()%Int.MAX` 作基准 id，理论上可能与既有 id 撞车导致 REPLACE 覆盖。
3. 提醒通知 `setOngoing(true)`，用户无法滑动清除，只能等状态变化时被 cancel。
4. `TodaySchedule.toTodayClass` 中 start==end 会被当成 24 小时长课。

### 踩到的两个坑（重要经验）
- **行号拼接漏函数**：用 Python 按行号替换大段代码时，`EmptyNotes` 夹在 `NoteRow` 和 `UndoButton` 之间，被一起删掉了 → 编译报 `Unresolved reference: EmptyNotes`。**教训：按行替换前先 grep 出区块内所有顶层声明的清单，替换后立刻核对一遍。**
- **`pointerInput` 的 block 只在 key 变化时重建**，里面的 lambda 会「冻」在创建那一刻。所以：
  - 决策用的普通值（如 `rowWidth` 派生的阈值）必须在 lambda 内**现读 state**，不能用外面算好的 val（否则永远是初始值 0）；
  - 回调统一用 `rememberUpdatedState` 包一层（`currentOnDragStart()` 等），避免读到过期闭包。
- 另外：滑出动画的目标位移要算上卡片左右各 12dp 的外边距，否则卡片会残留一条边。已抽成 `NOTE_ROW_H_PADDING` 常量。

## 表格视图时间段交集处理（第六轮，已完成）

**问题**：`WeekGrid` 的行是按 `(startTime, endTime)` **精确相等**匹配生成的。所以 `08:00-09:35` 和 `09:00-10:00` 这种相交但不相等的时段会排成上下两行，看起来像互不冲突。

**做法**：
- 新增 `data/TimetableBands.kt`（object，纯函数），`merge(slots)` 把时段按**有无交集**合并成 `Band`。用**扫描线**：按开始分钟排序，`slot.from >= runningEnd` 就另起一行，否则并入当前行并抬高 `runningEnd`（等价于求连通分量，能正确处理链式相交）。
- 用**分钟数**排序判交，不用字符串比较 —— 字符串字典序只对零填充的 `HH:mm` 成立。
- 首尾相接（`09:00` 接 `09:00`）**不算**交集，仍是两行。
- 行高改为 `max(基准行高, 56dp × 该行最多叠课数)`，避免一格叠多门课时卡片被压扁。
- 兜底：时间解析不出来 → 退回「一个时段一行」；`end <= start`（跨零点/脏数据）按 1 分钟算。两种都不会让课从表格里消失。

**抽成纯函数 + 补了 10 个单测**（`TimetableBandsTest`）—— 合并的边界（包含、链式相交、首尾相接、脏时间）在真机上没法验，只能靠单测盯。全部通过。

`assembleDebug` 成功，单测 **29 个**全绿（10 + 5 + 9 + 5）。

## 定位「展开反而变小」的根因（第十四轮，已完成）

用户贴了两张对比图（收起态 vs 展开态），要求定位缩小问题的代码、触发条件、复现步骤和修复方向。

### 根因
**`Modifier.heightIn(min = X)` 的 `X` 会被 Compose 用 `coerceIn` 夹进「父级传入的约束」里**。在 `DayColumn` 里，课程块的父级是 `BoxWithConstraints`，它的 maxHeight 就是**网格行的固定高度 `gridHeight`**。于是：

- 靠上方/中间的课：`X ≤ gridHeight`，min 生效 ✓
- **靠底部的课**：`X` 被夹到 `gridHeight`，而块本身的 y 已经接近 `gridHeight`，**可生长的空间几乎为 0** → 展开后长不动，看起来「没变大」甚至比收起态还小

而且 `naturalHeight` 本身就是按时间比例算的、接近列底，所以底部课程的展开几乎必然被夹住。

### 修法
1. 新增 `GRID_EXPANSION_ROOM = 120.dp`；选中时整行临时加高：`layoutGridHeight = gridHeight + (选中 ? 120dp : 0)`，Row 用它做 height。这样父级 maxHeight 变大，`heightIn` 的 min 不再被夹。
2. 课程块的定位**仍用 `gridHeight`**（时间刻度不能变），只有列高变大——多出来的 120dp 就是给底部课程向下生长的空间。
3. `DayColumn` 里「今天底色」原本用 `drawRect(size)` 会盖住新增的空白区，改成 `drawRect(Size(size.width, gridHeightPx))` 只铺到时间轴真实高度。
4. 底部 Spacer 从「选中时 140dp」收回固定 8dp——空间已由 `layoutGridHeight` 提供，两处叠加会导致多滚一大截。

### 顺带确认（未改动的部分）
- **宽度**：两态都是 `fillMaxWidth(widthFraction)`，与选中无关，不会缩小。
- **非选中块的高度**：`gridHeight × heightFraction`，与 `selectedId` 无关，选中别的块不会让它变小。
- 两张截图的裁剪范围/缩放比例不同（图 2 少了状态栏、整体约大 5%），直接比像素会有误差；真正的判据是「展开块的高度有没有超过它自己收起时的高度」。

## 时间轴改成分段线性（第十五轮，已完成）

### 设计
 新增 Focus(startMinute, endMinute) + Mapping + mappingOf(span, focus)：
- 无 focus → 线性（每分钟 1/span.minutes）
- 有 focus → **分段线性**：focus 段放大 FOCUS_SCALE = 2.2 倍（上限 MAX_FOCUS_SHARE = 0.62），其余分钟等比例压缩，**总高度不变**
- layout(dayClasses, mapping) 改为接收映射；左侧刻度、格线、块边界共用同一映射，永远对齐

### 两个被单测抓出来的真问题
1. **崩溃**：原本写 (base * FOCUS_SCALE).coerceIn(base, MAX_FOCUS_SHARE)。当 base > MAX_FOCUS_SHARE（比如 3 小时的课占 75%）时 coerceIn 的 min > max，**直接抛 IllegalArgumentException**。改成 .coerceAtMost(MAX).coerceAtLeast(base)——顺序不能反。

## 课表选中高亮的动画（第十八轮，已完成）

用户反馈：**课表选中时的高亮没有动画效果**。v3.8 加的是颜色类过渡，几何跳变漏掉了 —— 反馈是对的。

### 根因
`TimeAxis.mappingOf(span, focus)` 里 `focus` 是个**开关**：`share` 从 `base` 直接跳到 `(base × 2.2).coerceAtMost(0.62).coerceAtLeast(base)`。所以选中 / 取消选中一门课时，整列的**课程块、横线、左侧刻度**一起瞬移（颜色是渐变的，但被几何跳变盖住了，看起来就是「没动画」）。

### 改法 1：`mappingOf` 的 focus 从开关变连续量
- 新增 `progress: Float = 1f`，`share = base + (full - base) × progress.coerceIn(0f, 1f)`
- **关键性质**：`progress = 0` 时 `share == base`，此时 `focusPerMinute = otherPerMinute = 1 / span.minutes`，分段映射**精确退化成线性**。所以动画起点就是「没选中」的样子，中间每一帧都是合法映射 —— 不会出现「块和它自己的时间刻度对不上」（v3.6/v3.7 那两轮的老问题）
- UI 侧 `Animatable(0f)` 推 progress：`LaunchedEffect(focusTarget)` 里 0→1 展开、1→0 收回
- **A → B 直接换课**：先 `animateTo(0f, EXIT_MS)` 再展开 B。收完时 progress = 0（映射线性），换焦点那一刻正好接得上，不跳
- `heldFocus`：取消选中后 focusTarget 立刻变 null，但收起动画要知道往回收什么，所以单独留一份最近一次有效的焦点。**注意**：一开始想用「组合期写 state + 相等守卫」，改成 LaunchedEffect + Animatable 更干净（且 A→B 能两段式）
- 试过但**放弃**的方案：连焦点时段的两端一起做动画。因为 `share` 由 `base = 窗口宽度 / span` 推导，窗口从「整轴」缩到「一节课」的过程中 `base` 一直大于 `MAX_FOCUS_SHARE`，`share` 被地板夹成 `base` → 前半程完全是线性（无变化），拉伸全部挤在后半程，缓动很难看

### 改法 2：换高亮列时刻度 + 横线交叉淡入淡出
- 原来 `timeMarks` 整套瞬间替换（等距间隔 ↔ 那一天各事项的起止时刻）
- 横线从「每列各画一段」提到**一层铺满整个网格宽度**的底层（顺便消掉列间 1dp 断缝），和左侧刻度共用 `axisMarks` / `axisMarksPrev` + `axisCross` 两个 alpha
- 交叉进度用「步进计数」：`axisStep` 每次换刻度 +1，`axisProgress` 从 k 涨到 k+1，减 k 得 0→1
- **用 `LaunchedEffect(marksNow)` 而不是组合期写状态**：换刻度那一帧 `axisCross` 还是 1（旧的一套满的），晚一帧更新不会闪
- `DayColumn` 去掉 `timeMarks` 参数和画线逻辑，只留高亮底色；新增 `AxisMarkLabels(marks, alpha, mapping, gridHeight)`

### 其他
- `WeekGrid` 里网格主体从 `Row` 改成 `Box { 时间轴层; Row { 空刻度栏 + 各列 } }`，横线坐标从 `labelWidthPx` 起画

## 选中动画的性能（第十九轮，已完成）

用户反馈：**动画帧数表现不佳**。诊断结论：v3.9 让「选中放大」真正动起来之后，**动画期间每一帧都在重组整张网格**，而且每帧都在做大量无谓工作。动画时长 / 缓动 / 视觉效果一律没动，只压开销。

### 六个根因（都是「每帧」级别的浪费）
1. **`GridCell` 每帧重组**：`onClick` 是外层每帧新建的闭包（捕获每帧新建的 `Placed`），参数永不相等 → 跳过重组失效 → 每个块每帧重跑 4 个 `animate*AsState` + `Card`/`Surface` + 若干 `Text` + 一次子组合
2. **`BoxWithConstraints` 满天飞**：`DayColumn`（7 个）+ `GridCell`（每块 1 个）。`SubcomposeLayout` 在**内容 lambda 变化**时会重跑子组合，而内容 lambda 每帧都是新的 → 每帧白跑几十次子组合
3. **每帧分配**：`classes.filter{}` × 7、`marksNow` 重建、`busyDays` 重建
4. **组合跑两遍**：`mapping` 算在 `BoxWithConstraints` **外面** → 每帧先重组 `WeekGrid` 本体，再因子组合 lambda 变化重跑网格内容
5. **常驻图层**：`Modifier.pressable` 给每块常驻 `graphicsLayer`；`Modifier.alpha(1f)` 也给刻度文字常驻图层
6. **永不停止的动画**：状态圆点呼吸用 `rememberInfiniteTransition` → App 永远进不了空闲帧

### 改法（要点）
- **让 `GridCell` 参数跨帧稳定**：`onClick` 改收 `ClassEntity`（不收闭包）；块高**不传原始值**，改传 `showRoom` / `showDetails` 两个布尔（只在跨 46dp / 76dp 阈值时才变）→ 绝大多数帧直接跳过重组。**这一步最关键**：一开始我把 `blockHeight: Dp` 直接传进去，它每帧都变，等于白改
- 删掉 `DayColumn` / `GridCell` 的 `BoxWithConstraints`：列宽由调用方传 `columnWidth`，块高阈值由调用方算好（新增 `BLOCK_ROOM_MIN_HEIGHT` / `BLOCK_DETAILS_MIN_HEIGHT` 常量）
- `byDay` / `days` / `marksNow` 全部 `remember` 住
- **`mapping` 的读取点挪进 `BoxWithConstraints` 内部** → 每帧被失效的只剩网格这一层子组合，`WeekGrid` 本体不再跟着重组（组合从两遍降到一遍）
- `Modifier.pressable` 只在真的按下时才挂 `graphicsLayer`；刻度文字 `alpha` 只在 <1 时才挂图层
- **去掉状态圆点呼吸动画**（保留颜色过渡）——唯一一条永不停止的动画

### 验证过但没改的
块高每帧变化会让块内 `Text` 重新排版：`TextLayoutResult.canReuse` 会比较 `constraints.maxHeight`（源码在 `foundation/text/TextLayoutHelper.kt`，当 `softWrap || overflow == Ellipsis` 时比较），所以约束变了就不复用。
但 `MultiParagraphIntrinsics` 是缓存的（`TextDelegate.layoutIntrinsics`），单行短文本的实际开销很小；而改成 `wrapContentHeight(unbounded = true)` 稳定约束会让 46~63dp 的块里 3 行标题**溢出**（现在的行为是按可用高度省略号截断），不值得。

### 排查方法（可复用）
Compose 的 API 细节直接从 gradle 缓存的 sources jar 里查，比凭记忆猜准：
```

```
本轮查的是 `androidx.compose.ui/ui-text-android/1.6.0/.../ui-text-android-1.6.0-sources.jar` 和 `androidx.compose.foundation/foundation-android/1.6.0/.../foundation-android-1.6.0-sources.jar`。

## 选中项原地放大 + 动画收敛（第二十轮，已完成）

需求：① 便签界面 / 课表列表界面单击高亮后，该条目**独立扩大**，表现力更强；② 适当降低动画复杂度让帧数稳定。

### 1. 选中项独立放大
- 新增常量 `SELECTED_SCALE = 1.05f`，选中时 `graphicsLayer { scaleX/scaleY = 1 + (1.05-1) * selection }`
- **用 graphicsLayer 而不是改尺寸**：它不参与布局 → 原地长大、不挤开邻居、不用重排文字，比改尺寸便宜得多
- 放大后要盖住相邻条目：便签行 `zIndex` 改成三档（拖动 2 > 选中 1 > 普通 0）；课表卡片选中时 `zIndex(1f)`（在 Column 里有效）
- **1.05 是算出来的上限**：便签行左右各留 12dp（行宽 ≈ 336dp）→ 1 + 24/336 ≈ 1.071；课表卡片左右各留 10dp（卡宽 ≈ 340dp）→ 1 + 20/340 ≈ 1.059。取 1.05 两边都安全
- 便签选中阴影 0 → 4dp（原来是 0）

### 2. 一个条目只跑一条动画（关键简化）
原来便签行选中跑 **6 条** `animate*AsState`（色条 / 底色 / 文字色 / 描边色 / 描边粗细 / 阴影），课表卡片和表格课程块各 4 条。每条都是独立的一路动画、各自逐帧失效重组。

改法：新增 `rememberSelectionProgress(selected)`（一条 0→1 的 tween），所有属性由它 `lerp`：
```kotlin
val selection = rememberSelectionProgress(selected)
val containerColor = lerpColor(surface, primaryContainer, selection)
val borderWidth   = lerpDp(1.dp, 1.5.dp, selection)
val selectedScale = 1f + (SELECTED_SCALE - 1f) * selection
```
- 便签行 6 → 1（阴影因拖动还需单独一条），课表卡片 4 → 1，表格课程块 4 → 1
- 附带好处：各属性天然同步，原来多条动画「各自启动」会有细微错拍
- `lerp` 需要两个不同包的同名函数，用 import 别名区分：`androidx.compose.ui.graphics.lerp as lerpColor`、`androidx.compose.ui.unit.lerp as lerpDp`

### 3. 顺带削掉的复杂度
- `pressSpec()` 由 `spring(dampingRatio = 0.55f, ...)` 换成 `tween<Float>(120)` —— 弹簧来回震荡帧数不可预测；随之 `Spring` / `spring` 两个 import 删除
- 课程块详情淡入去掉 `delayMillis = 60`

## 主界面切换的帧率（第二十一轮，已完成）

用户反馈：**各个主界面互相切换的帧率过低**。根因是 v3.8 给顶部栏加的「切页时折叠」动画。

### 根因（有源码依据）
`Scaffold` 的 `contentPadding.top` **直接取顶栏的测量高度**：
```kotlin
// androidx/compose/material3/Scaffold.kt
top = if (topBarPlaceables.isEmpty()) insets.calculateTopPadding() else topBarHeight.toDp()
```
所以 `expandVertically` / `shrinkVertically` 每改一次高度，内容区的约束就变一次：
1. `WeekGrid` 的 `BoxWithConstraints` 读到新的 `maxHeight` → **每帧重新组合**，`gridHeight` 重算、所有课程块重新定位
2. 每个块的 `Card` 高度跟着变 → 块内 `Text` 的 `maxHeight` 约束每帧在变。文字布局缓存的 key 里带 `constraints`（`foundation/text/TextLayoutHelper.canReuse`，`softWrap || overflow == Ellipsis` 时比较 `maxHeight`）→ **每帧对每个块重新排版文字**

240ms ≈ 14 帧，每帧都在做这些事 → 帧率塌。

### 改法
1. **顶栏去掉高度动画**：`AnimatedVisibility(expandVertically/shrinkVertically)` → 普通 `if (selectedTab == 0)`。代价是没有折叠动画，换来整屏约束恒定
2. **Tab 内容过渡 `ExitTransition.None`**：旧页面立刻退场。过渡期间只画一层页面（课表那屏很重）；旧页面也不会因为顶栏消失导致的布局变化而「跳一下」。新页面保留 `fadeIn + slideInHorizontally`

### 顺带确认（重要，省得下次再查）
`Scaffold` 在**顶栏槽位没有内容**时会自动改用状态栏内边距，所以「便签页有顶栏、其它页没有」时两边顶部留白都是对的，不用额外加 `windowInsetsPadding`。

### 可复用经验
判断 Compose 动画是否会导致**每帧布局失效**，先看它改的东西是不是别人的**约束**：
- 改 `graphicsLayer`（alpha / scale / translation）→ 只重绘，便宜
- 改 `Modifier.offset { }` / `drawBehind { }` 里读的状态 → 只重排/重绘该节点，便宜
- 改**尺寸 / padding / 父级高度** → 整棵子树换约束 → 重组 + 重排 + 文字重排，贵

## 课表列表的高亮线条（第二十三轮，已完成）

需求：课表**列表界面**的高亮线条太粗糙，希望从线条粗细 / 抗锯齿 / 渐变 / 阴影几方面做精致化。用 AskUserQuestion 确认了范围，用户选择**给课表列表加选中高亮并精修线条**。

   - 光晕：向外扩 3dp 描一圈 α0.14 主色。**用主色而不是 `shadow`** —— 阴影是灰的、跟主题无关，光晕取自主色，浅色/深色都能融入

## v3.15 课表高亮视觉层级与主题自适应（本轮完成）

**目标**：优化课表列表高亮 — 对比度与可读性、统一悬停/选中/当前节次样式、增强过渡与微交互、保持简洁。

**核心设计：四级强度收敛成一条进度**
`HighlightSpec.of(baseContainer, baseTitle, selection, accent, pressed, hovering)` 返回一个 data class，
把「弱(今天) / 中(悬停) / 按下一档 / 强(选中)」用 `maxOf(weak*0.30, hover*0.46, down*0.62, selection)` 收成单一 level，
再由它 lerp 出 barBrush / barWidth / borderColor / borderWidth / glowColor / containerColor / titleColor。
**关键取舍**：用 maxOf 不是相加 —— 否则同时成立会「叠出第五种颜色」。

**层级表（浅色 / 深色分别标定，这是本次最大价值点）**
- 竖条：idle α0.16 0.30×宽 → 弱 α0.30 0.56×宽 → 选中 纵向渐变 1×宽
- 描边：idle outline α0.78 → 选中 主色 1.6dp（HL_BORDER_WIDTH）
- 光晕：只在强档。浅色 α0.17 / 深色 α0.30
- 容器：primaryContainer 混合 —— 浅色 0.72 / 深色 0.88
- 标题：浅色向 onPrimaryContainer 靠 0.85（加深）；**深色只靠 0.55** —— 因为深色主题的
  onPrimaryContainer 是 #D6E4FF（浅色），靠过去会变亮、与底色对比不升反降。靠底色变深来拉开。

**对比度硬事实（改动的依据）**
- 原描边 `onSurface α0.07` 对白卡片只有 **1.05:1**，等于没画 → 浅色改用主题 `outline`
- 深色下**灰描边不可用**：onSurface(#E0E0E0) 与 surface(#1E1E1E) 差 1.78:1，深底上看不见灰线 → 深色改走主色+透明度
- Theme.kt 的 `outline` 提亮：浅 `#B4BBC5`→`#9AA3AF`，深 `#5A6169`→`#6B737C`

**动效**
- 进/出非对称：`SELECT_ENTER_MS=280` / `SELECT_EXIT_MS=180`（取消是「撤销」，别拖泥带水）
- `HOVER_MS=120` 悬停；`rememberHoverProgress(interaction)` 用 collectIsHoveredAsState
- 同一个 MutableInteractionSource 同时喂悬停与按下，两档反馈同源，不会「悬停亮、按下灭」

**统一**
- `drawHighlightLines` 从 10 个散参改成收一个 `HighlightLines` 对象；便签行与课表卡片共用同一几何
- 便签行的色条也改用它 —— 两个列表的色条落在同一条线上
- 表格列头加悬停底色 + clip 圆角；DayColumn 高亮加左右 1dp 主色边线（光靠浅底在密集网格里读不出列边界）
- **删掉 v3.14 遗留的重复定义**（`drawHighlightLines` 与 `HL_*` 常量曾各写两遍）和已无调用方的 `Modifier.pressable`

**有意为之的取舍**：表格里的课程块**不加选中高亮**。格子只有 40~76dp、文字占满，
再叠描边+光晕会盖住信息本身 → 只保留 hover/press 即时反馈（0.5px 描边 + 1dp 抬升 + 2% 缩放）。
